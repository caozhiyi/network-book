# 卷六导读：混合云网络

云上的网络做得再完整，企业也很少只活在云上。数据库、核心系统、合规设备、历史包袱，往往还留在 IDC；于是问题不再是两个 VPC 能不能互通，而是两套世界观并不相同的网络如何稳定地接在一起。云上的设计偏向弹性、自动化和按需开通，IDC 里的设计却常常背着既有设备、既有地址规划和既有运维习惯前行。两边各有道理，也各有包袱。一旦真的要连，差异就会从概念层面落到最具体的地方：路径够不够稳，带宽够不够用，路由能不能控，故障来了是不是能切，拓扑扩张之后还能不能继续管得住。

互联网加密隧道来得快，但抖动和带宽未必可控；物理专线质量更好，但建设和维护成本显著更高；当 VPC 和 IDC 的数量继续增长，连接本身又会反过来要求被统一管理。真正的难点从来不在“有没有一条线”，而在路径质量、路由控制、故障切换与拓扑收敛能否同时成立。混合云听起来像一个产品词，落到网络上，仍然是同一个问题：复杂性究竟被放在了哪里。是把复杂性交给公网质量，交给专线建设，交给路由策略，还是交给统一控制面，不同选择背后，成本、可控性和演进方式都会完全不同。
